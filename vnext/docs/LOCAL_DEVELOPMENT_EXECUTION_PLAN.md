## 2. P0 blockers before any execution permission expansion
- E01 scope: ScopeChecker maps both build and test to local:exec; SECURITY.md currently claims local:test is sufficient, inconsistent with source. Split narrowly scoped test/build/git read/git network/git mutation/maintenance permissions; explicitly document legacy scope compatibility and deny implicit new powers. Check caller AND device AND project AND runner policy. Existing live capability list does not expose test/build on either device; exact token claims not independently inspected.
- E02 denied work: TaskRouter creates local tasks before handlers check live capability; handlers explicitly return queued even for ineligible target. Preserve PR22 transient read-only queue behavior and PR23 explicit offline routing; distinguish authoritative denial from temporary unavailable/legacy unknown. Persist authorized policy revision and target binding; reject known unauthorized side effects before persistence, revalidate at claim and before execution. Explicit offline opt-in only for safe cases; default no queued mutations on unknown/denied devices. Test M14 regression and generic submit bypass, revocation/regrant, idempotency replay and scope filtering.
- E03 Windows: current built-ins choose npm.cmd/flutter.bat and spawn with shell:false; Windows wrapper compatibility must be proven on native ARM64. Resolve trusted absolute executables and fixed wrapper templates (no interpolated caller shell fragments); do not globally enable shell:true.
- E04 child env: executeProcessWithoutShell merges all process.env and extraEnv, potentially exposing AGENT_TOKEN to arbitrary project code. Explicit child environment allowlist, no control/config/admin/device/OAuth/Cloudflare/Kaggle credentials; never leak via output or command line. Audit effective OS permissions: environment filtering is not a sandbox, same-user project code may access config/IPC or modify agent. Use separate low-privilege execution identity or equivalent enforceable isolation with protected config/release/IPC and narrowly scoped repository credentials; demonstrate negative access checks before production host execution. No signing secrets by default.
- E05 lifecycle: current process runner accumulates stdout/stderr unbounded, no explicit timeout/process-tree cleanup. Bound logs/output bytes and retention, process lifetime and tree cancellation (Windows job object or tested equivalent), distinguish cancellation requested from confirmed exit, keep lock/uncertain mutation state until audited. Do not use wildcard kill. A stale result is terminal; never return pending or retry as new mutation. Initial patch in this PR addresses bounded local result stale handling only. Also review TaskStore.cancelTask stale exclusion before adding maintenance.
- E06 project privileges: WS1 reports all six projects hostExecution=true including Desktop/Downloads; WS2 two read-only. Do not grant local:exec to those broad roots; require dedicated narrow repo roots, protected local policy, explicit per-runner allowlists, expected checkout state. WS2 stays read-only until separate operator approval. Arbitrary repo scripts, git hooks, build scripts and dependency installers are code execution, not sandboxed by argv validation.
- E07 inventory: add task_inventory and device_maintenance_check with minimal metadata, filters, stable pagination/snapshot revision, explicit complete flag, redaction and scope isolation. Existing CLI local readiness is not full Gateway emptiness. Cover active all backends for gateway updates and stale/quarantined local records; no false PASS on partial view or missing permission. Never expose ADMIN_SECRET.
- E08 drain: persisted per-device admission gate, atomic with task submission/claim on both Node and DO, restart/hibernation safe. Maintenance begins with new submissions blocked; allow already admitted tasks to drain under defined policy; no claim of unapproved pending work, no auto-cancel mutation. Return lease/task evidence; resume requires matching maintenance generation and operator authorization. Kill switch remains distinct emergency control, not routine drain.

## 3. Capability contracts (proposed names; not yet implemented)
All local requests require explicit targetDeviceId and projectId for new tools, server-side validated payload and clientRequestId. No caller-provided executable, environment, shell text, unvalidated argv or absolute filesystem path. Resolve canonical repo/work directory within root, use policy revision and expectedHead where relevant. No hidden changes to existing tools. Return taskId and durable status; terminal stale is manual reconciliation. Existing legacy operations retain tested semantics unless migration explicitly approved.
| Tool family | Allowed operations / guards |
|---|---|
| Git read | git_status reuse; git_diff/log with bounded output, no external diff/textconv; validate refs, no option injection, restrict paths, redact remote credentials |
| Git network | fetch approved remote/ref; pull only ff-only and clean expected branch/HEAD, no implicit merge/rebase; pinned HTTPS/SSH remote policy and credential helper isolation; disable unapproved protocols/submodules/hooks |
| Git mutation | create/switch branch with validated names, no dirty overwrite; stage explicit relative paths and expected hashes, commit with expectedHead and explicit message, push only approved feature branch with expected remote ref; no force push, reset --hard, clean -fd, delete branch, direct main push, or implicit commit of secrets |
| Flutter | fixed IDs pub_get, analyze, test, build_apk_debug, build_apk_release, build_aab; build mode/target/flavor from local allowlist, artifact path/hash/size; release signing/publish separate operator gate |
| Dart | analyze/test/format_check; format write is mutation; explicit approved files |
| Android | SDK/Java/Gradle/adb version and adb devices read-only; fixed Gradle wrapper tasks test/assemble; APK install requires explicit device serial and approval; no adb shell or arbitrary Gradle arguments |
| Node | npm test/build; npm ci separate dependency mutation profile with locked dependencies and explicit script policy; no arbitrary npm scripts from remote request |
| Python | approved interpreter/venv, pytest fixed profile, version/requirements read; dependency installation separate approved profile, never arbitrary pip or Python code |
| Inventory / health | task_inventory, device_maintenance_check, device_status enriched with session, version, tool availability, policy revision and last verified observation; no secrets or raw reconnect proof |
| Maintenance | device_drain/device_resume persisted generation, explicit authorization, atomic submission/claim gate; no automatic destructive task resolution |

## 4. Implementation waves and acceptance
A. PR 28 foundation: audit register + contract, stale terminal response regression; next implement E01/E02/E04/E05/E06 security core before any privilege grants. Use local isolated Windows test fixtures; CI both runtime paths and regenerate tracked dist.
B. Inventory and maintenance E07/E08: reuse admin query projection, test global/limited views, pagination race, stale/queued distinction, drain concurrency, DO hibernation, unauthorized scope, restart, resume generation, and unchanged Kaggle/Swarm.
C. Git read then network then mutation: fixtures with local disposable bare remotes, hostile ref/path, dirty branch, non-fast-forward, hooks/config, credential redaction, retry/fencing, explicit target isolation. No production push or credential access.
D. Runner profiles: Flutter/Dart/Android first (Astor TuneUp actual nested repo discovery; do not assume its configured root is repo); then Node/Python. Test ARM64 .cmd/.bat launch, PATH with spaces/metacharacters, cancellation/child tree, env/ACL isolation, log limits, missing tool, artifact hashing. Use disposable fixture before actual project; verify local build outputs, no signing/upload. P1 platform parity only if target required; macOS/iOS not implied by Windows Android readiness.
E. Deployment: verified compiled dist and CI, independent review, inventory + maintenance gate, version-pinned rollout one device at a time. OAuth client and device grant migration explicit and separately authorized; no automatic token reissue or admin credential sharing. Prove only intended project(s) can execute; WS2 stays read-only; do not use production unauthorized-write negative probes. Production 1006 smoke and re-login autostart remain separate from initial cutover acceptance. Rollback preserves current immutable releases/config/scheduled task and known Worker version.
