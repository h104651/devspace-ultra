# MCP Insufficient-Scope Step-Up Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make authenticated MCP tool calls that lack a required OAuth scope return the standard HTTP 403 Bearer `insufficient_scope` challenge so ChatGPT can perform OAuth scope step-up and retry.

**Architecture:** Keep the existing OAuth allowlist and task-level authorization boundaries unchanged. Adapt the deployed `GatewayDurableObject` export at the Cloudflare HTTP transport boundary: inspect MCP tool-error responses, convert only determinable `AUTH_FORBIDDEN ... Missing: 'scope'` failures into an OAuth challenge, and leave ordinary MCP tool errors untouched. This avoids duplicating or weakening authorization logic in `TaskRouter` while preserving the existing Durable Object class name required by the Cloudflare migration.

**Tech Stack:** TypeScript, Cloudflare Durable Objects, MCP 2026-07-28 stateless HTTP transport, OAuth 2.1 / RFC 6750 / RFC 9728, Node assert test harness, GitHub Actions.

**Spec:** MCP scope step-up behavior (SEP-2350 / current MCP SDK behavior) and RFC 6750 `insufficient_scope` semantics.

## Global Constraints

- Do not auto-grant `local:write` or weaken `TaskRouter` scope checks.
- Do not add `local:exec`, `raw_shell:run`, or admin scopes.
- Preserve existing successful tool-call response behavior.
- Preserve ordinary non-authentication tool errors as MCP `isError` tool results.
- For authenticated insufficient-scope failures, emit HTTP 403 plus `WWW-Authenticate: Bearer error="insufficient_scope"` with the missing `scope` and same-origin `resource_metadata` URL.
- Follow TDD: regression test must fail on the current base before production code changes.
- Base branch is `feature/vnext-remote-gateway` at `75f52b2a43c6283119bcbeea2579bb12d9cb6cbb`.
